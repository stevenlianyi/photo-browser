# photo-browser UI 设计

> 版本：v0.2 ｜ 日期：2026-10-04 ｜ 平台：Web 桌面优先 / 响应式
> 定位：**本地个人/家庭照片浏览与人脸归类工具**（单用户、内网/本机运行）
> 技术栈：**Vue 3 + Vite + Pinia + Tailwind CSS + Element Plus**（从零搭建，不复用 contentHub 基线）
> 说明：本稿为**简化版**，先对齐信息架构与关键交互；视觉 Token 见第七节（双套变量 + 跟随系统）。
> 视觉方向：**浅色淡雅 + 照片优先** —— 低饱和中性色 + 大留白 + 极轻阴影，让照片成为页面里唯一的高对比元素。

## 一、设计目标

### 1.1 产品定位 → 设计命题

photo-browser 把磁盘上散落的照片，变成**可按人浏览、可跨年代追溯**的私人相册。它**不是**在线相册（不上传、不社交），而是**本地资产 + 人脸归类工作台**。

| # | 命题 | 对设计的约束 |
|---|---|---|
| 命题一 | 主对象是「照片」与「人」两条轴 | 一级导航就分「照片流」与「人物库」，二者互相可达 |
| 命题二 | 归类的准确性靠**人工确认**兜底 | 「待确认队列」必须是**一级入口且带角标**，不能藏在二级 |
| 命题三 | 扫描是**限流批处理**（每批默认 100 张后暂停） | 扫描页必须显式展示「本批进度 / 已暂停等待指示」，允许**断点续扫** |
| 命题四 | 原图**只读、不改写** | 所有操作只动数据库与缓存，UI 不提供"编辑/覆盖原图" |
| 命题五 | **机器会认错，纠错要就近、可撤销** | 用户在照片流里看到认错，**当场一次点击就能改**；机器认的和人工确认的要能一眼分辨；不可逆操作留撤销入口 |

### 1.2 设计原则（P0，冲突时按序让位）

| 优先级 | 原则 | 说明 |
|---|---|---|
| P0-1 | **人脸框永远可见** | 照片详情里检测到的人脸用框标出，已归属/待确认用颜色区分 |
| P0-2 | **不确定就要问，不要猜** | 相似度落在灰区（`T_low`–`T_high`）一律进待确认队列，不静默归属 |
| P0-3 | **批量动作做减速** | 合并人物、删除照片等不可逆操作需参数复述 + 二次确认 |
| P0-4 | **进度诚实** | 扫描进度用真实计数（已处理/总数），不做假进度条 |
| P0-5 | **原图零风险** | 任何操作不得导致原图被改写或删除（删除仅软删库记录） |
| **P0-6** | **纠错要就近** | 浏览时发现认错，人脸框悬停即出「✗ 不是他」，**不许绕到人物详情**。自动归属用虚线框与人工确认的实线框区分，用户才知道哪些值得复核 |
| **P0-7** | **错要能收回** | 合并/拆分不可逆，必须留撤销入口（操作日志）；标记陌生人等永久排除操作要二次确认 |

### 1.3 设计红线（不做）

- ❌ 不做社交/分享/点赞——这是私人工具。
- ❌ 不做云上传（本机资产，不出硬盘）。
- ❌ 不做"一键自动归类并直接生效"——必须经人工确认环节。
- ❌ 不在缩略图网格里加载原图（必须先出缩略图，点击才加载原图）。
- ❌ **不隐藏「机器认的」**——自动归属与人工确认必须视觉可区分，否则用户无从纠错。
- ❌ **不把纠错入口藏深**——「✗ 不是他」必须在人脸框悬停可达。

## 二、用户场景

| ID | 场景 | 用户目标 | 关键痛点（设计要解决） |
|---|---|---|---|
| **S1** | 导入并扫描照片 | 把新照片纳入库并按人归类 | 照片多，一次全跑太久；怕误解锁/误判 |
| **S2** | 按人浏览 | 看"某个人"从小到大的照片 | 跨年龄差异大，需要按年代看 |
| **S3** | 待确认归类 | 把没归属的人脸归到对的人 | 不确定是"本人/亲属/陌生人"，需要并排比对 |
| **S4** | 按时间/地点浏览 | 找"某年某地"的照片 | 需要时间轴 + 地点筛选 |
| **S5** | 查重清理 | 找出重复/废片 | 需要内容级去重提示 |
| **S6** | 纠错（合并/拆分） | 合并同名不同人 / 拆分错并的人 | 合并不可逆，需要可核对 + **可撤销** |
| **S7** | **改判（最高频）** | 浏览时发现「这张脸认错了」 | 机器认的和人工确认的混在一起，看不出哪些可疑；纠错入口绕太远 |

```

│         │  ┌──────┐  │           │ 相机  Canon EOS 350D     │
│         │  │ 人脸1│  │← 绿=已归属 │ 尺寸  3072×2048          │
│         │  └──────┘  │           │ 地点  北京 · 家            │
│         │     ┌─────┐│           │ 文件  sha256:9f3a…        │
│         │     │人脸2││← 橙=待确认 │                          │
│         │     └─────┘│           │ ── 出现的人 ──            │
│         │   （大图）  │           │ ● zhongwen lian  0.86 ✓  │
│         └────────────┘           │ ◐ 未知人脸 #2    [确认▸] │
│                                  │                          │
│                                  │ [标记重复] [软删除]      │
└──────────────────────────────────┴─────────────────────────┘
```

> **人脸框三种描边**（区分归属来源，DR-16）：
> **实线** = 人工确认 ｜ **虚线** = 机器自动认的（`isConfirmed=0`，**可否决**）｜ **点线** = 待确认
> 悬停人脸框即出「**✗ 不是他**」，**一次点击可达** —— 用户在照片流里看到认错的第一反应就是就地纠正，不该绕到人物详情。改判浮层：改判到候选 / 新建人物 / 置为未知 / 标记为陌生人。
> 侧栏「出现的人」每行同样带「✗ 改判」。

```

│ ‹ 人物库   ┌──┐  zhongwen lian   [合并到…] [撤销上次合并] [编辑] │

│  时间轴  │  人脸样本                                        │
├──────────┼─────────────────────────────────────────────────┤
│ 1998–2000 │ ✓ 人工确认 412   ▣▣▣▣▣▣▣▣▣▣                   │
│ 2005–2009 │ ⌁ 自动归属  74   ▣ ▣ ▣ ▣ ▣ ▣ ▣  [✗ 移除]        │
│ 2010–2014 │ ⌁ 自动归属  38   ▣ ▣ ▣ ▣ ▣         [✗ 移除]        │
│ 2015–2019 │ ───────────────────────────────────────────        │
│ 2020–2024 │ ⌁ 自动归属  36   ▣ ▣ ▣ ▣            [✗ 移除]        │
│          │ ⚠ 自动 ≫ 确认，识别质量偏低，建议人工确认 74 张  │
└──────────┴─────────────────────────────────────────────────┘
```

> 时间轴**按年代桶分组**（对齐 S0 结论：分桶是刚需），直观呈现跨年龄漂移。
> 人脸样本**必须分两段**：人工确认（实线）与自动归属（虚线）。混在一起用户无法判断哪些值得复核。
> **质心健康度提示**（DR-16）：「自动 ≫ 确认」时主动提示，用数据引导用户去纠错，而不是等他自己发现。
> **「撤销上次合并」**只对拆分/合并开放（合并不可逆，没有日志就回不去）。

### 4.6 P-06 待确认队列 ★（核心人工环节）

```
┌────────────────────────────────────────────────────────────┐
│ [ 待确认 214 ] [ 我不同意 37 ]         [跳过] [忽略此人脸]   │
├────────────────────────────────────────────────────────────┤
│  ┌──────────┐         候选人物（按相似度排序）              │
│  │          │   ┌──┐ zhongwen lian   0.62  [✓ 确认]         │
│  │ 未知人脸 │   └──┘                                        │
│  │  （大图）│   ┌──┐ luwen lian      0.58  [确认]           │
│  │          │   └──┘   ⚠ 兄妹，长相接近                       │
│  │  来源：  │   ┌──┐ zhongming lian  0.41  [确认]           │
│  │ DSC02580 │   └──┘                                        │
│  └──────────┘   ─────────────────────────────              │
│                 无匹配 → [新建人物]  [标记为陌生人]          │
├────────────────────────────────────────────────────────────┤
│  相似度均在灰区（0.30–0.45），需人工判断                     │
└────────────────────────────────────────────────────────────┘
```

- **并排比对**：未知人脸 vs 候选人物头像，一目了然。
- 候选按相似度排序，灰区（`T_low`–`T_high`）条目标橙色提示。
- 支持键盘：`1/2/3` 选候选，`N` 新建，`S` 跳过，`I` 忽略。
- **双 Tab**（DR-16）：「待确认」（`personCode IS NULL AND isStranger=0`）+「我不同意」（`personCode IS NOT NULL AND isConfirmed=0`，即**机器自动认的**）。

**Tab 2「我不同意」**（申诉入口）

```
┌────────────────────────────────────────────────────────────┐
│ 扫描任务                                     [＋ 新建扫描]  │
├────────────────────────────────────────────────────────────┤
│ 任务        状态        本批       累计        操作         │
│ SJ-0007   ◐运行中      62/100    1,240      [暂停]         │
│ SJ-0006   ⏸已暂停      100/100   3,800   [继续下一批]      │
│ SJ-0005   ✓完成        —         9,204      [查看]         │
│ SJ-0004   ✕失败        —         120        [查看错误]     │
└────────────────────────────────────────────────────────────┘
```

- **批次限流语义**：每处理 `batchSize`（默认 100）张即 `⏸已暂停`，**等待人工点「继续下一批」**。
- 进度用真实计数（已处理/本批），不用假进度条。
- 失败可展开原始错误（如解码失败、路径无权限）。

## 六、交互状态

### 6.1 状态机

```
扫描任务 jobStatus
  IDLE ──► RUNNING ──┬──► PAUSED ──(继续)──► RUNNING
                     ├──► DONE
                     └──► FAILED

照片 scanState
  0待扫描 ──► 1已入人脸库 ──┬──► 2待人工确认 ──► 3完成
                            └──► 3完成（自动全部归属）

人脸归属（四态，DR-16）
  未归属(点线橙) ──(确认)──► 人工确认(实线绿) ──(改判)──► 人工确认(别人)
        │                          ▲
        │                      (机器认错了)
        │                          │
        └──(自动归属，虚线绿)────────┘   ← 「我不同意」列表的来源
        └─(忽略)──► 陌生人(灰，不再出现)
```

| 状态 | 语义色（浅/深） | 描边 | 图标 | 文字 |
|---|---|---|---|---|
| RUNNING | 信息 `#5B8DEF` / `#7BA6F5` | — | ◐ 脉冲 | 运行中 |
| PAUSED | 警告 `#E8A33D` / `#F0B45F` | — | ⏸ | 已暂停 |
| DONE | 成功 `#2E9E6B` / `#4FBE8A` | — | ✓ | 完成 |
| FAILED | 危险 `#E05A5A` / `#F07A7A` | — | ✕ | 失败 |
| 待确认人脸 | 警告 | **点线** | ⚠ | 待确认 |
| 自动归属人脸 | 成功 | **虚线** | ◐ | 机器认的，可否决 |
| 人工确认人脸 | 成功 | **实线** | ✓ | 已确认 |
| 陌生人 | 弱文本 | 无 | ⊘ | 陌生人 |

> **四重编码**（色 + 描边 + 图标 + 文字），保证灰度/色盲下可辨；描边样式额外承担「归属来源」这一维信息。

### 6.2 关键交互流程

```
流程一：导入 → 扫描 → 归类
  P-07 新建扫描（选根目录，批大小=100）
    └─ RUNNING：处理 100 张 → PAUSED
         └─ [继续下一批] → RUNNING → … → DONE
              └─ 未归属人脸 → P-06「待确认」Tab（角标+1）
              └─ 自动归属人脸 → P-06「我不同意」Tab（角标+1）

流程二：待确认归类（主链路）
  P-06 未知人脸 vs 候选
    ├─ [确认] → pb_photo_person(source=1) + pb_face.isConfirmed=1 → 下一条
    ├─ [新建人物] → 建 pb_person → 归属 → 下一条
    └─ [忽略] → 标记陌生人 → 下一条

流程三：合并纠错
  P-05 [合并到…] → 选目标人物 → ConfirmMerge（复述双方信息）→ 二次确认 → 合并
     └─ 合并不可逆 → 提供「撤销上次合并」（pb_review_log，isRevertible=1）

流程四：浏览中发现认错（纠错主链路，DR-16）
  P-02/P-03 悬停人脸框（虚线绿 = 机器认的）→ [✗ 不是他]
    ├─ [改判到…] 选候选 → 删旧 linkKey + 写新 source=1 + 重算原人与新人质心
    ├─ [置为未知] → personCode=NULL → 回到「待确认」Tab
    ├─ [新建人物] → 建档并归属
    └─ [标记陌生人] → isStranger=1 → 永久排除（二次确认）
  P-06「我不同意」Tab → 按照片整张否决（≤2 次点击）或簇内批量改判
```

### 6.3 反馈与确认

| 场景 | 反馈 | 二次确认 |
|---|---|---|
| 开始/继续扫描 | 状态条更新 | 否 |
| 确认一张人脸归属 | Toast 绿 + 队列前进 | 否（可撤销 60s） |
| **改判归属（✗ 不是他）** | Toast + 两个角标同时刷新 | 否（Toast 内 60s 可撤销） |
| **标记陌生人** | Toast + 该脸从所有队列消失 | **是**（永久排除，不可逆） |
| **合并人物 / 拆分** | — | **是**（ConfirmMerge 复述双方信息）；事后可「撤销」 |
| 软删除照片 | — | **是**（danger 确认） |
| 改识别阈值 | 提示"需重新生成质心" | 否（引导） |

### 7.4 主题策略（三态）

| 项 | 规则 |
|---|---|
| 默认 | **浅色** |
| 跟随系统 | `@media (prefers-color-scheme: dark)` 自动切深色同色系 |
| 手动开关 | TopBar 提供「浅色 / 深色 / 跟随系统」三态，写 `localStorage`，首屏读取避免闪白 |
| Element Plus | 在 `html.dark` class 下同步切换，并覆盖其 CSS 变量（`--el-bg-color` / `--el-text-color-primary` / `--el-border-color` 等） |

> **照片区特例**：照片本身按真实色彩渲染，**不施加任何滤镜**（浅色/深色下都保持原样）。
> 界面用低饱和中性色 + 大留白 + 极轻阴影，让高饱和的照片内容成为页面里唯一的高对比元素。
