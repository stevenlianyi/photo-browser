# photo-browser UI 设计

> 版本：v0.2 ｜ 日期：2026-10-04 ｜ 平台：Web 桌面优先 / 响应式
> 定位：**本地个人/家庭照片浏览与人脸归类工具**（单用户、内网/本机运行）
> 技术栈：**Vue 3 + Vite + Pinia + Tailwind CSS + Element Plus**（从零搭建，不复用 contentHub 基线）
> 说明：本稿为**简化版**，先对齐信息架构与关键交互；视觉 Token 见第七节（双套变量 + 跟随系统）。
> 视觉方向：**浅色淡雅 + 照片优先** —— 低饱和中性色 + 大留白 + 极轻阴影，让照片成为页面里唯一的高对比元素。

---

## 一、设计目标

### 1.1 产品定位 → 设计命题

photo-browser 把磁盘上散落的照片，变成**可按人浏览、可跨年代追溯**的私人相册。它**不是**在线相册（不上传、不社交），而是**本地资产 + 人脸归类工作台**。

| # | 命题 | 对设计的约束 |
|---|---|---|
| 命题一 | 主对象是「照片」与「人」两条轴 | 一级导航就分「照片流」与「人物库」，二者互相可达 |
| 命题二 | 归类的准确性靠**人工确认**兜底 | 「待确认队列」必须是**一级入口且带角标**，不能藏在二级 |
| 命题三 | 扫描是**限流批处理**（每批默认 100 张后暂停） | 扫描页必须显式展示「本批进度 / 已暂停等待指示」，允许**断点续扫** |
| 命题四 | 原图**只读、不改写** | 所有操作只动数据库与缓存，UI 不提供"编辑/覆盖原图" |

### 1.2 设计原则（P0，冲突时按序让位）

| 优先级 | 原则 | 说明 |
|---|---|---|
| P0-1 | **人脸框永远可见** | 照片详情里检测到的人脸用框标出，已归属/待确认用颜色区分 |
| P0-2 | **不确定就要问，不要猜** | 相似度落在灰区（`T_low`–`T_high`）一律进待确认队列，不静默归属 |
| P0-3 | **批量动作做减速** | 合并人物、删除照片等不可逆操作需参数复述 + 二次确认 |
| P0-4 | **进度诚实** | 扫描进度用真实计数（已处理/总数），不做假进度条 |
| P0-5 | **原图零风险** | 任何操作不得导致原图被改写或删除（删除仅软删库记录） |

### 1.3 设计红线（不做）

- ❌ 不做社交/分享/点赞——这是私人工具。
- ❌ 不做云上传（本机资产，不出硬盘）。
- ❌ 不做"一键自动归类并直接生效"——必须经人工确认环节。
- ❌ 不在缩略图网格里加载原图（必须先出缩略图，点击才加载原图）。

## 二、用户场景

| ID | 场景 | 用户目标 | 关键痛点（设计要解决） |
|---|---|---|---|
| **S1** | 导入并扫描照片 | 把新照片纳入库并按人归类 | 照片多，一次全跑太久；怕误解锁/误判 |
| **S2** | 按人浏览 | 看"某个人"从小到大的照片 | 跨年龄差异大，需要按年代看 |
| **S3** | 待确认归类 | 把没归属的人脸归到对的人 | 不确定是"本人/亲属/陌生人"，需要并排比对 |
| **S4** | 按时间/地点浏览 | 找"某年某地"的照片 | 需要时间轴 + 地点筛选 |
| **S5** | 查重清理 | 找出重复/废片 | 需要内容级去重提示 |
| **S6** | 纠错 | 合并同名不同人 / 拆分错并的人 | 合并不可逆，需要可核对 |

- 进度用真实计数（已处理/本批），不用假进度条。
- 失败可展开原始错误（如解码失败、路径无权限）。

## 五、组件规范（精简）

| 层级 | 组件 |
|---|---|
| L1 基础 | Button / Input / Select / Table / Tabs / Drawer / Modal / Toast / Pagination（Element Plus + Tailwind） |
| L2 业务 | **FaceBox**（人脸框叠加） / **FaceThumb**（人脸小图） / **PersonCard** / **PhotoThumb** / **CandidateRow**（候选人物行） / **BucketTimeline**（年代桶时间轴） / **ScanProgress** / **ConfirmMerge**（合并确认） |

| 关键组件 | 规格 | 约束 |
|---|---|---|
| `FaceBox` | 绝对定位框，2px 描边 | 已归属=绿（浅 `#2E9E6B` / 深 `#4FBE8A`），待确认=橙（浅 `#E8A33D` / 深 `#F0B45F`），悬停显示人名+相似度；**颜色+图标+文字三重编码** |
| `PhotoThumb` | 1:1 或 4:3，圆角 8 | 只加载缩略图；角标（👤/⚠/📷）；hover 上浮 2px / 120ms ease-out |
| `CandidateRow` | 头像 + 姓名 + 相似度 + 确认按钮 | 相似度降序；灰区橙色提示 |
| `BucketTimeline` | 年代桶分组横向缩略图带 | 桶数自适应；空桶不显示 |
| `ConfirmMerge` | 合并弹窗 | **复述双方姓名+照片数**，动词按钮「确认合并」 |

## 六、交互状态

### 6.1 状态机

```
扫描任务 jobStatus
  IDLE ──► RUNNING ──┬──► PAUSED ──(继续)──► RUNNING
                     ├──► DONE
                     └──► FAILED

照片 scanState
  0待扫描 ──► 1已入人脸库 ──┬──► 2待人工确认 ──► 3完成
                            └──► 3完成（自动全部归属）

人脸归属
  未归属(橙) ──(确认)──► 已归属(绿)
             └─(忽略)──► 陌生人
```

| 状态 | 语义色（浅/深） | 图标 | 文字 |
|---|---|---|---|
| RUNNING | 信息 `#5B8DEF` / `#7BA6F5` | ◐ 脉冲 | 运行中 |
| PAUSED | 警告 `#E8A33D` / `#F0B45F` | ⏸ | 已暂停 |
| DONE | 成功 `#2E9E6B` / `#4FBE8A` | ✓ | 完成 |
| FAILED | 危险 `#E05A5A` / `#F07A7A` | ✕ | 失败 |
| 待确认人脸 | 警告 | ⚠ | 待确认 |
| 已归属人脸 | 成功 | ✓ | 已确认 |

> **三重编码**（色 + 图标 + 文字），保证灰度/色盲下可辨。

### 6.2 关键交互流程

```
流程一：导入 → 扫描 → 归类
  P-07 新建扫描（选根目录，批大小=100）
    └─ RUNNING：处理 100 张 → PAUSED
         └─ [继续下一批] → RUNNING → … → DONE
              └─ 未归属人脸 → P-06 待确认队列（角标+1）

流程二：待确认归类（主链路）
  P-06 未知人脸 vs 候选
    ├─ [确认] → pb_photo_person(source=1) + pb_face.isConfirmed=1 → 下一条
    ├─ [新建人物] → 建 pb_person → 归属 → 下一条
    └─ [忽略] → 标记陌生人 → 下一条

流程三：合并纠错
  P-05 [合并到…] → 选目标人物 → ConfirmMerge（复述双方信息）→ 二次确认 → 合并
```

### 6.3 反馈与确认

| 场景 | 反馈 | 二次确认 |
|---|---|---|
| 开始/继续扫描 | 状态条更新 | 否 |
| 确认一张人脸归属 | Toast 绿 + 队列前进 | 否（可撤销 60s） |
| 忽略/标记陌生人 | Toast + 队列前进 | 否 |
| **合并人物** | — | **是**（ConfirmMerge） |
| 软删除照片 | — | **是**（danger 确认） |
| 改识别阈值 | 提示"需重新生成质心" | 否（引导） |

### 7.2 语义色（双套，保证两套主题下对比度均达 WCAG AA）

| 语义 | 浅色 | 深色 | 用途 |

> ⚠️ **状态识别不得单靠颜色**：一律「颜色 + 图标 + 文字」三重编码，保证灰度/色盲下可辨。

### 7.3 字体 / 圆角 / 间距 / 图标

| 项 | 取值 |
|---|---|
| 字体 | Inter + PingFang SC；hash/编码用 JetBrains Mono |

| 圆角 | 卡片 12 / 按钮 8 / 缩略图 8 |
| 间距 | 4px 基准 |

### 7.4 主题策略（三态）

| 项 | 规则 |
|---|---|
| 默认 | **浅色** |
| 跟随系统 | `@media (prefers-color-scheme: dark)` 自动切深色同色系 |
| 手动开关 | TopBar 提供「浅色 / 深色 / 跟随系统」三态，写 `localStorage`，首屏读取避免闪白 |
| Element Plus | 在 `html.dark` class 下同步切换，并覆盖其 CSS 变量（`--el-bg-color` / `--el-text-color-primary` / `--el-border-color` 等） |

> **照片区特例**：照片本身按真实色彩渲染，**不施加任何滤镜**（浅色/深色下都保持原样）。
> 界面用低饱和中性色 + 大留白 + 极轻阴影，让高饱和的照片内容成为页面里唯一的高对比元素。

## 八、响应式与无障碍（简要）

- **断点**：桌面基准 1440；<1024 侧栏收窄为图标；<768 网格 2 列、详情转上下布局。
- **移动端能力边界**：仅浏览 + 轻操作（确认归类）；**扫描/合并/删除**提示到桌面端。
- **无障碍**：WCAG 2.1 AA；人脸框除颜色外带图标/文字；全流程键盘可达（待确认队列支持数字键快捷）；焦点可见。
