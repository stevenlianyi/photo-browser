### 1.3 人脸识别现状（准确度强化的基础）

现有体系已相当完整，**不是从零开始**：

| 环节 | 现状 | 可调项 |
|---|---|---|
| 阈值 | 三套预设（conservative / balanced / aggressive），当前 **conservative** | `T_LOW=0.35`、`T_HIGH=0.55` |
| 年代分桶 | adaptive 策略：0–18 岁 3 年 / 18 岁以上 10 年，相邻桶取 max | `BUCKET_*` 系列、`MATCH_NEIGHBOR_BUCKETS` |
| 质心 | 只用人工确认样本，防污染 | `MIN_CENTROID_SAMPLES=3`、`CENTROID_CONFIRMED_ONLY` |
| 检测 | SCRFD，`det_thresh=0.5` | `engine/face/engine.py` |
| 聚类 | DBSCAN，余弦距离 eps 可调 | `DBSCAN_EPS`、`DBSCAN_SIM_CELLS` |
| 实测成绩 | 误拒率 **32.75% → 约 19%**（降幅 42%） | — |

## 三、图片策略（关键决策，需你拍板）

手册要"带图片"，但本项目没有现成图片资源，且有三条现实约束：

1. **隐私**：真实家庭照片不能进 git
2. **成本**：每个界面截图都要起服务、造数据、点到位
3. **维护**：界面一改，截图就过期

| 方案 | 内容 | 优点 | 缺点 |
|---|---|---|---|
| **A. SVG 示意图**（推荐） | 界面线框图 + 流程图 + 状态机图，手绘可控 | 无隐私风险、体积小（几 KB）、永不"过期"、可精准表达流程 | 不如真实截图直观 |
| **B. playwright 截图** | 用 `.playwright-cli` 截真实界面 | 最真实 | **含人脸数据**，只能本地看不入库；界面改动即过期 |
| **C. ImageGen 氛围图** | 生成"家庭相册 / 老照片重逢"意象图 | 首屏感染力强 | 无法表达具体界面操作 |

**建议：A 为主（功能示意）+ C 做首屏 hero + 手册里嵌入「界面拓扑图」说明信息架构。**

> 说明：B 方案可以本地跑一份给自己看，但**不作为手册素材入库**。

## 四、人脸识别准确度强化（分投入档，先测再改）

### 4.1 前置：必须先建评测基线（不做这步，一切"强化"都无法证明）

- 从现有库（36756 张）取**人工确认过的人脸**构建评测集，按人分档抽样
- 指标：**误拒率 FRR**、**误受率 FAR**、**灰区占比**（灰区越宽，人工负担越重）
- 输出基线报告，作为后续每一项改动的对照

> ⚠️ 没有基线就调参 = 拍脑袋。当前 32.75% → 19% 这个数字是**特定数据集**上的结果，
> 换库后是否成立未知，必须先在自己库上复测。

### 4.2 低成本高收益项（P1，先做这些）

| 项 | 做法 | 预期收益 | 风险 |
|---|---|---|---|
| **TTA 水平翻转** | 正反两张 embedding 取平均再比对 | 通常 FRR 降 1–3 个百分点 | 低，计算量 ×2 |
| **质量加权** | 相似度按 `detScore` + 短边 + 模糊度加权，而非一视同仁 | 减少低质量脸拖累质心 | 低 |
| **待确认队列按信息增益排序** | 优先展示"最不确定、影响最大"的脸 | 同等人工量下准确度收益最大化 | 低，纯排序 |

### 4.3 中成本项（P2，评测后再决定）

| 项 | 做法 | 备注 |
|---|---|---|
| 阈值自适应 | 按库规模 / 人均确认样本量动态选预设 | 需先验证三套预设在自己库上的表现 |
| 邻桶策略调优 | `MATCH_NEIGHBOR_BUCKETS` 1 → 2 的收益验证 | 已可配，需评测 |
| 模型升级评估 | buffalo_l → 更高精度模型 | CPU 推理速度会掉，需权衡 |

### 4.4 交付物

- 评测脚本（可复现、有随机种子）
- 基线报告 + 每项改动前后的对照表
- 若某项收益 < 0.5 个百分点，**不采纳**（避免为改而改）

## 七、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 评测集太小，结论不可信 | "强化"变成自我安慰 | 按人分层抽样，报告里写清样本量与置信区间 |
| TTA 让扫描耗时翻倍 | 10 万张库体验下降 | 先测单张耗时，决定是否全量启用或只对质心样本启用 |
| SVG 示意图与实际界面有偏差 | 手册可信度下降 | 每张图标注"示意图"，与 UI 设计文档的 ASCII 布局对齐 |
| 范围蔓延到新功能开发 | 计划失控 | 严守第二节"不做"清单 |
