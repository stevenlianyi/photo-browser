相认相册 Sightseen

把磁盘上散落的照片，按人相认——跨年代、跨翻拍，也能认出同一个人。本地运行，照片不上传、不出本机。

本地运行 · 无需联网 原图只读 · 绝不改动 无需 GPU · 单机即可 零安装数据库 · SQLite 单文件

一、这是什么

相认相册 Sightseen 是一个本地优先的照片浏览与人脸归类系统，对标 Picasa 3 但更轻。它把磁盘上散落的照片，变成可按人浏览、可跨年代追溯的家庭相册。最大的不同是：它真正帮你认出同一个人——二十年前的照片和今天那张，是同一个他，被相认、归到一起。

  • 纯浏览、不编辑原图（原文件只读，绝不写 / 删 / 改名）。
  • 人脸识别 + 归类是核心：按联系人出生年月把每个人按年代分档识别，跨年龄也能保持高准确率。
  • 人员数据来自通讯录（CSV / vCard 导入）。
  • 规模可达 10 万张照片；单机；无需 GPU、无需装数据库服务。
存储SQLite（单文件、零安装）
后端Python + FastAPI + 原生 sqlite3
前端Vue3 + Vite + Tailwind + Element Plus
📍 软件只做浏览与归类，不会改动你的任何一张原图。删除 / 改名照片请回到文件管理器操作。

二、你家的照片，是不是也这样

大多数家庭照片库，不是"缺功能"，而是"找不到人、记不准时间地点"。相认相册就是为这几件最痛的事而做：

🧓

翻拍老照片，认不出是谁

扫描件 / 翻拍件里的人脸，被自动归进了"翻拍那年"，和本人几十年的照片彻底断开。

📅

老照片不知道是哪年

EXIF 写的是翻拍时刻，时间轴全乱了；想按年代找回"我小时候那张"却怎么都翻不到。

📍

地点记不准、也改不了

GPS 漂了几十公里，目录名只写了"大概那一片"，明明是"外婆家"却没处记。

🔍

找某个人要翻半小时

10 万张里找一个人，像大海捞针；重复照片还混在一起，分不清该留哪张。

下面三件事，正是相认相册专门解决的——而且都不会改动你的原图。

三、三大核心能力

① 按人相认 · 跨年代也能认出同一个人

导入通讯录（带出生年月）后，软件会把每个人按年龄分档识别：同一张脸，3 岁、13 岁、33 岁、63 岁都归到同一个人名下，而不是每次年龄一变就"认生"。

相似度落在灰区的脸不会静默归类，而是进"待确认"队列，由你点一下认领——既不让机器乱认，也不让你瞎翻。认错了还能一键改判、置未知、新建或标记陌生人，并且可撤销。

✅ 实测：引入年代分档后，误拒率从 32.75% 降到约 19%（降幅约 42%）——也就是说，更多"确实是同一个人"的脸被正确认回来了。

② 修正拍摄年代 · 老照片也能归回正确的年代

翻拍件 / 扫描件的年份，扫描器读到的是翻拍那一刻（EXIF / 文件名 / 文件时间给的都是它）。于是这张照片里的人脸，全落在了错误的年代档——一位 1938 年生的人，会被错归到"2016–2025"。

在照片详情里点「修正拍摄年代」，填一个真实年份（比如 1960），软件会先把受影响的人列出来（谁、从哪个年代档、到哪个年代档），确认后再重算。扫描器读到的原始年份不会被改写，随时可以「恢复自动」。

💡 这是照片级修正：一张合影里不同生日的人，会各自朝正确的方向变——所以软件坚持先给你看"影响面"，再落库。

③ 修正地点 · 一眼能说出"这是外婆家"

某张照片的地点其实是错的：GPS 漂了几公里、目录名只是"大概那一片"、或者整批照片干脆没有地点线索。你明明知道"这是外婆家"，库里却没处记。

在照片详情点「修正地点」，下拉选已有地点或行政区，也可以直接输入新名字（如"外婆家"）。提交前会先算清地点字典怎么变（哪个地点加几张、哪个减几张），提交后字典立刻重建。原值不改写，随时「恢复自动」。

💡 自己起的地名（如"外婆家"）会被记为人工命名——以后重扫、逆地理都不会再把它覆盖掉。

四、功能全景

  • 照片流 / 时间线：按拍摄时间浏览全部照片，支持左右翻页（← →）。
  • 人物库：按人归类照片，显示人物头像，可查看某人跨年代的时间轴。
  • 待确认队列：相似度落在灰区的人脸进入队列，由你确认归属，不静默归类。
  • 我不同意：自动归属但未经确认的脸在此，支持整张照片一键否决。
  • 纠错闭环：浏览时发现认错了，一次点击可改判 / 置未知 / 新建 / 标陌生人，且可撤销。
  • 修正拍摄年代 核心：照片详情里把翻拍件归回真实年代，先列影响面再落库，可「恢复自动」。
  • 修正地点 核心：把漂移 / 缺失的地点改对，可自定义地名（如"外婆家"），提交后重建地点字典。
  • 年代抽样：人物详情里，从"他出现过的每一年"抽一张照片排成等间隔队列，可打包带走——看"这个人每一年长什么样"。
  • 重复比对：照片流里的"重复照片"筛选可并排对比两张是否同一张、元数据差异、两边人脸是否被认成不同人；只标记、不删原图。
  • 人工旋转：扫描方向不对的照片可旋转显示（0/90/180/270），原图一个字节都不动。
  • 地点维度：人物 → 地点列表 → 时间线，查看某人"去过的地方"（含境内中文名）。
  • 联系人导入：CSV / vCard 导入人员名单（带出生年月），作为归类依据。先「预览导入计划」（只算不写），确认后再导入。
  • 扫描台：后台扫描、断点续扫、限流。
  • 双主题：浅色淡雅 / 深色 / 跟随系统，偏好写入 localStorage。

五、准确度是怎么炼成的

"认人"这件事最怕两种错：把 A 认成 B（误受），以及明明是同一个人却没认出来（误拒）。相认相册用四道机制把这两种错都压住：

42%
年代分档后误拒率降幅
3 档
阈值预设可切换
0
自动归属动用未确认样本

① 年代分档

同一人的脸随年龄变化很大。分档策略按出生年自适应：0–18 岁每 3 年一档、18 岁以上每 10 年一档，比对时取相邻三桶的最大值。这是把误拒率从 32.75% 压到约 19% 的关键。

② 质心防污染

用于比对的"标准脸"（质心）只用你人工确认过的样本算出来——机器自己猜的脸绝不进标准。某一年龄档确认样本 < 3 张时，退到兜底档；总确认样本 < 3 张时，该人不参与自动匹配，交给待确认队列。这样即便早期机器猜错，也不会"污染"后续判断、越错越多。

③ 三档阈值预设

相似度落在 T_low–T_high 之间称为灰区，灰区里的脸不自动归类，进待确认队列。三档预设（默认 conservative）：

预设T_lowT_high取舍
s0（基准）0.350.55唯一有实测数据背书的档位
conservative（默认）0.420.62自动归属门槛最高、误归属最少、灰区最宽
aggressive0.300.48人工量最少，代价是误归属会上升
⚠️ 家庭照片库里，"把 A 认成 B"的代价远高于"多让你点几下确认"。所以默认偏保守——宁可多确认几张，也不乱认。确认过一大半后，可在设置里切到激进档少点几下。

六、隐私承诺

家庭照片是最私人的数据。相认相册从架构上保证它只属于你：

✓ 纯本地运行，不联网、不上传、不调用任何云端识别 API。
✓ 原图目录 绝对只读——不写、不删、不改名、不覆盖。
✓ 缩略图与裁剪图是生成物，可随时从原图重建。
✓ 人脸特征只存在本机 SQLite 单文件里，换机器拷贝即走。
✓ 单用户设计，没有登录、没有账户、没有多用户概念。
✓ 所有"写"操作只动数据库与缩略图，碰不到原图一个字节。

七、快速上手

一句话版（已装好依赖 + 已有照片库时）

在仓库根目录执行：

.\start.cmd

然后打开 http://127.0.0.1:8765 。Ctrl+C 停止。也可以直接双击 start.cmd。

⚠️ 启动失败时窗口会停住等你按键，不会一闪而过、让你对着空窗口发呆。

第一次跑（换机器 / 新克隆仓库）

# ① 建 venv（必须用官方源，本机默认镜像查不到 vobject）
py -3.13 -m venv code\.venv
code\.venv\Scripts\python.exe -m pip install -i https://pypi.org/simple -r requirements.txt
code\.venv\Scripts\python.exe -m pip uninstall -y opencv-python      # 只留 headless

# ② 前端依赖 + 构建（Node 必须 >= 22）
cd code\webserver; npm install; npm run build; cd ..\..

# ③ 本机配置（该文件 .gitignore，不入库）
copy code\src\config\local_settings.py.example code\src\config\local_settings.py
notepad code\src\config\local_settings.py          # 改 PHOTO_ROOT 指向你的照片目录

# ④ 建库 + 扫描（只需一次）
code\.venv\Scripts\python.exe code\src\tools\build_db.py
code\.venv\Scripts\python.exe code\src\tools\scan_cli.py --root d:\PhotoLib\photo

# ⑤ 起服务
.\start.cmd

为什么是 .cmd 而不是 .ps1

PowerShell 5.1 在执行策略为 Restricted / AllSigned 时会拒绝运行 .ps1。.cmd 由 cmd.exe 执行、不受该策略约束，双击也能跑。

⚠️ 不要为了跑本项目去改 PowerShell 执行策略（Set-ExecutionPolicy）——那是机器 / 用户的安全设置。若你本来就想放开，那是你自己的决定：Set-ExecutionPolicy -Scope CurrentUser RemoteSigned。

start.cmd 参数

参数作用
（无）起服务，同源提供前端 → 开 8765
--dev另起 Vite dev server → 开 5173（改前端代码热更时用）
--check-only只做体检、不启动。改配置后先跑这个
--port 8799换端口（8765 被占时）
--db <路径>换库文件（对着另一个库试调时）
--root <路径> / --thumb <路径>覆盖原图根 / 缩略图根（本进程有效，退出即失效）

首次使用三件事

1. 照片要先放进图片目录、再扫描才看得到。增加照片需先复制到图片目录（默认 d:\photoLib\photo），然后在「扫描任务」里启动新扫描才会被收录。
2. 「待确认」需要你先人工确认几张脸才有内容。自动归属只用人工确认过的样本算质心（防污染），所以刚上手时「我不同意」与自动归属都是空的，这是正确行为不是故障。确认几张脸以后（至少三张），到「扫描任务」里再跑一遍匹配（人脸识别），就会自动识别你已人工确认的人；你人工确认的越多，识别的准确度越高，照片年代越准，整体准确率越高。
3. 人员档案从「设置 → 联系人导入」进来（Outlook 导出的 CSV / 手机导出的 vCard）。先「预览导入计划」（只算不写），确认无误再「确认导入」。

八、配置与参数

本机配置 local_settings.py

复制示例文件后修改（该文件不入库）：

copy code\src\config\local_settings.py.example code\src\config\local_settings.py
notepad code\src\config\local_settings.py

其中最重要的是 PHOTO_ROOT，指向你的照片目录。

常用工具命令（在 code\src 下用 venv 解释器）

命令用途
tools\build_db.py建库（幂等，老库升级补建缺的表）
tools\scan_cli.py --root <目录>扫描原图目录
tools\gen_thumbs.py缩略图补建
tools\import_contacts.py联系人导入（CSV / vCard；界面上在「设置 → 联系人导入」）

⚠️ 所有 Python 命令务必用 code\.venv\Scripts\python.exe，裸敲 python 会命中 WindowsApps 基础解释器，依赖不同导致行为诡异。

九、备份与恢复

⚠️ 备份 / 恢复必须停服务（先 Ctrl+C）。服务开着时拷走的是 SQLite 的 WAL 中间态，备份「成功」但会少最近几分钟的确认记录。
# 用 .venv 的解释器
code\.venv\Scripts\python.exe code\src\tools\backup.py backup                            # 备份 db\ + thumb\
code\.venv\Scripts\python.exe code\src\tools\backup.py list                              # 列已有备份
code\.venv\Scripts\python.exe code\src\tools\backup.py restore --code pb_20261007153012  # 恢复（先自动另存现状）
  • 不备份 photo\（原图只读且不会坏）——「恢复」= 让索引回到某个时刻，不找回删掉的照片。
  • 设置页只有只读清单 + 可照抄的命令，故意没有备份按钮（页面上唯一的写操作是「联系人导入」）。

十、常见问题

Q：页面打开了但照片列表是空的？

照片要先扫描才看得到。库为空时界面照样起得来。请先跑一次 scan_cli.py --root <你的照片目录>，或用 .\start.cmd --check-only 体检。

Q：「待确认」「我不同意」都是空的？

这是正确行为。自动归属只用人工确认过的样本算质心，刚上手时还没有确认样本，需要先人工确认几张脸。

Q：老照片的年份 / 地点是错的，能改吗？

能。照片详情里分别有「修正拍摄年代」和「修正地点」——改的是照片级标注，原图不动，随时可「恢复自动」。详见三大核心能力。

Q：双击 start.cmd 一闪而过 / 报脚本禁止运行？

脚本本身是 .cmd，不受 PowerShell 执行策略约束。若仍异常，请在仓库根目录的命令行里手动执行 .\start.cmd 查看报错。

Q：端口 8765 被占用了？

换端口：.\start.cmd --port 8799。注意：端口被占时，8765 上可能跑着另一个库的服务，请在浏览器确认数据是否一致。

Q：改了前端代码没生效？

改完前端要重新 npm run build；本地热改用 .\start.cmd --dev（开 5173）。并确保 dist/ 已构建（否则根路由只返回 JSON，页面全 404）。

Q：怎么恢复误删的照片？

软件不删除原图，也不备份 photo\。原图删除只能靠你自己的文件备份找回；backup.py 只恢复索引（数据库 + 缩略图）。
