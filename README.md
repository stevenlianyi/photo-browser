# 相认相册 Sightseen

> **相认**（xiāng rèn）：在照片里认出那个人。
>
> 本地个人 / 家庭**相册** —— 把磁盘上散落的照片，按人相认，跨年代也能认出同一个人。
> 存储：**SQLite（单文件、零安装）** ｜ 后端：Python + FastAPI + 原生 sqlite3 ｜ 前端：Vue3 + Vite + Tailwind + Element Plus
>
> 信任徽章：**本地运行 · 不上传云端** ｜ **原图只读 · 绝不改动** ｜ **无需 GPU · 单机即可** ｜ **零安装数据库**

---

## 一、这是什么

一个**本地优先**的家庭相册 + 人脸归类系统，对标 Picasa 3 但更轻。把磁盘上散落的照片，按人相认，串成一个可跨年代追溯的私人相册。最大的不同是：它真正帮你**认出同一个人**——二十年前的照片和今天那张，是同一个他，被相认、归到一起。

- **纯浏览、不编辑**原图（原文件只读，绝不写 / 删 / 改名）。
- **人脸识别 + 归类**是核心优势：按联系人**出生年月**把每个人按**年代分档**识别，跨年龄也能保持**高准确率**（实测误拒率从 32.75% 降到约 19%）。
- **人员数据来自通讯录**（CSV / vCard 导入）—— 这是多数开源方案满足不了的部分。
- 规模约 **10 万张**照片；单机；**无需 GPU、无需装数据库服务**。

| 项 | 说明 |
|---|---|
| 存储 | SQLite（单文件、零安装） |
| 后端 | Python + FastAPI + 原生 sqlite3 |
| 前端 | Vue3 + Vite + Tailwind + Element Plus |

> 📍 软件**只做浏览与归类**，不会改动你的任何一张原图。删除 / 改名照片请回到文件管理器操作。

---

## 二、你家的照片，是不是也这样

大多数家庭照片库，不是"缺功能"，而是"找不到人、记不准时间地点"。相认相册就是为这几件最痛的事而做：

- **🧓 翻拍老照片，认不出是谁**：扫描件 / 翻拍件里的人脸，被自动归进了"翻拍那年"，和本人几十年的照片彻底断开。
- **📅 老照片不知道是哪年**：EXIF 写的是翻拍时刻，时间轴全乱了；想按年代找回"我小时候那张"却怎么都翻不到。
- **📍 地点记不准、也改不了**：GPS 漂了几十公里，目录名只写了"大概那一片"，明明是"外婆家"却没处记。
- **🔍 找某个人要翻半小时**：10 万张里找一个人，像大海捞针；重复照片还混在一起，分不清该留哪张。

下面三件事，正是相认相册专门解决的——而且都**不会改动你的原图**。

## 三、三大核心能力

### ① 按人相认 · 跨年代也能认出同一个人

导入通讯录（带出生年月）后，软件会把每个人按**年龄分档**识别：同一张脸，3 岁、13 岁、33 岁、63 岁都归到同一个人名下，而不是每次年龄一变就"认生"。相似度落在**灰区**的脸不会静默归类，而是进"待确认"队列，由你点一下认领；认错了还能一键改判、置未知、新建或标记陌生人，**并且可撤销**。

> ✅ 实测：引入年龄分桶后，误拒率从 **32.75% 降到约 19%**（降幅约 42%）——更多"确实是同一个人"的脸被正确认回来了。

### ② 修正拍摄年代 · 老照片也能归回正确的年代

翻拍件 / 扫描件的年份，扫描器读到的是**翻拍那一刻**（EXIF / 文件名 / 文件时间给的都是它），于是这张照片里的人脸全落在了错误的年代档。在照片详情里点「修正拍摄年代」，填一个真实年份（比如 1960），软件会**先把受影响的人列出来**（谁、从哪个年代档、到哪个年代档）再落库。扫描器读到的原始年份**不会被改写**，随时可以「恢复自动」。

### ③ 修正地点 · 一眼能说出"这是外婆家"

某张照片的地点其实是错的：GPS 漂了几公里、目录名只是"大概那一片"、或整批照片没有地点线索。在照片详情点「修正地点」，下拉选已有地点或行政区，也可以**直接输入新名字**（如"外婆家"）。提交前会先算清**地点字典怎么变**，提交后字典立刻重建。自己起的地名会被记为**人工命名**——以后重扫、逆地理都不会再把它覆盖掉。

## 四、快速开始

### 一句话版（已装好依赖 + 已有照片库时）

在仓库根目录执行：

```powershell
.\start.cmd
```

然后打开 **http://127.0.0.1:8765** 。`Ctrl+C` 停止。也可以**直接双击 `start.cmd`**。

> 启动失败时窗口会停住等你按键 —— 不会一闪而过、让你对着空窗口发呆。

> ⚠️ **为什么是 `.cmd` 不是 `.ps1`**：PowerShell 在执行策略为 `Restricted` / `AllSigned` 时会拒绝运行 `.ps1`。`.cmd` 由 cmd.exe 执行、不受该策略约束，双击也能跑。
> ⚠️ **不要为了跑本项目去改 PowerShell 执行策略**（`Set-ExecutionPolicy`）—— 那是机器 / 用户的安全设置。

## 五、首次使用须知

1. **照片要先放进图片目录、再扫描才看得到。** 增加照片需要先复制到所选择的图片目录（默认 `d:\photoLib\photo`），然后在「扫描任务」里启动一个新的扫描任务才会被收录。库里 0 张照片时界面照样起得来，只是列表是空的。
2. **「待确认」需要你先人工确认几张脸才有内容。** 自动归属只用人工确认过的样本算质心（防污染），所以刚上手时「我不同意」与自动归属都是空的，**这是正确行为不是故障**。

## 六、主要功能与界面

- **照片流 / 时间线**：按拍摄时间浏览全部照片，支持左右翻页（`←` `→`）。
- **人物库**：按人归类照片，显示人物头像，可查看某人跨年代的时间轴。
- **待确认队列**：相似度落在灰区的人脸进入队列，由你确认归属，不静默归类。
- **我不同意**：自动归属但未经确认的脸在此，支持整张照片一键否决。
- **纠错闭环**：浏览时发现认错了，一次点击可改判 / 置未知 / 新建 / 标陌生人，且可撤销。
- **修正拍摄年代** <sup>核心</sup>：照片详情可人工指定这张照片的拍摄年（老的翻拍件 / 扫描件），改完刷新全部相关人脸的年代桶；先给影响面、可「恢复自动」。
- **修正地点** <sup>核心</sup>：照片详情可把**这一张**的地点改成别的地点 / **从行政区里选**（离线地理数据集的规范名，约 2,840 个区县 + 34 个省级，选它会**并入同一个区县那一项**）/ 自由输入一个新地名（「外婆家」）/ 清空回自动；地点详情可**重命名**显示名（同一个选择器）。改动都会**先给影响面**（那一项多少张 → 多少张），提交后**立刻重建地点字典**（计数即时正确），且**都不写纠错日志、都完全可逆**。
- **年代抽样**：按人、按年抽一张（加权随机 + 种子可复现），可打包成 zip——看"这个人每一年长什么样"。
- **重复比对**：照片流里可筛选重复照片并**并排对比**两张是否同一张、元数据差异、两边人脸是否被认成不同人；只标记、不删原图。
- **照片旋转**：左右转 90°，**只影响显示**（不烘进图片、不改 EXIF）。
- **地点维度**：**地点 → 照片流**（列表按中文名归并同名地点、可下钻到每个来源地），某人的「去过的地方」是人物详情里的一个区块（含境内中文名）。
- **联系人导入**：CSV / vCard 导入人员名单，作为归类依据（入口在**设置页 → 联系人导入**：先预览计划，再导入）。
- **扫描台**：后台扫描、断点续扫、限流。
- **双主题**：浅色淡雅 / 深色 / 跟随系统，偏好写入 localStorage。

## 七、准确度是怎么炼成的

"认人"这件事最怕两种错：把 A 认成 B（**误受**），以及明明是同一个人却没认出来（**误拒**）。相认相册用四道机制把这两种错都压住：

1. **年龄分桶**：按联系人出生年月把每个人按年代分档识别（0–18 岁 3 年 / 18 岁以上 10 年），比对时取相邻三桶的最大值。这是把误拒率从 32.75% 压到约 19% 的关键。
2. **质心防污染**：用于比对的"标准脸"（质心）**只用你人工确认过的样本**算出来——机器自己猜的脸绝不进标准。某一年龄档确认样本 < 3 张时，退到兜底档；总确认样本 < 3 张时，该人**不参与自动匹配**，交给待确认队列。
3. **三档阈值预设**：相似度落在 `T_low`–`T_high` 之间称为**灰区**，灰区里的脸不自动归类，进待确认队列。三档预设（默认 **conservative**）：

   | 预设 | T_low | T_high | 取舍 |
   |---|---|---|---|
   | `s0`（基准） | 0.35 | 0.55 | 唯一有实测数据背书的档位 |
   | `conservative`（默认） | 0.42 | 0.62 | 自动归属门槛最高、误归属最少、灰区最宽 |
   | `aggressive` | 0.30 | 0.48 | 人工量最少，代价是误归属会上升 |

   > ⚠️ 家庭照片库里，"把 A 认成 B"的代价远高于"多让你点几下确认"。所以默认偏保守——宁可多确认几张，也不乱认。确认过一大半后，可在设置里切到激进档少点几下。

4. **待确认闭环**：人工确认过的脸回流为质心样本，越用越准。

### 人脸四态

| 状态 | 条件 | 进「待确认」 | 进「我不同意」 |
|---|---|---|---|
| 未归属 | `personCode IS NULL AND isStranger=0` | ✅ | — |
| 自动归属（未人工确认） | `personCode NOT NULL AND isConfirmed=0 AND isStranger=0` | — | ✅ |
| 人工确认 | `isConfirmed=1` | — | — |
| 陌生人 | `isStranger=1` | — | — |

## 八、隐私承诺

家庭照片是最私人的数据。相认相册从架构上保证它**只属于你**：

- ✅ 纯本地运行，**不联网、不上传、不调用任何云端识别 API**。
- ✅ 原图目录 **绝对只读**——不写、不删、不改名、不覆盖。
- ✅ 缩略图与裁剪图是**生成物**，可随时从原图重建。
- ✅ 人脸特征只存在**本机 SQLite 单文件**里，换机器拷贝即走。
- ✅ 单用户设计，**没有登录、没有账户、没有多用户**概念。
- ✅ 所有"写"操作只动数据库与缩略图，**碰不到原图一个字节**。

## 九、照片库布局

**根目录由配置决定**：`code/src/config/local_settings.py` 的 `PHOTO_ROOT`，**默认 `d:\PhotoLib`**。

```
d:\PhotoLib\
├── photo\        原图 —— 【绝对只读】，应用绝不写入
├── thumb\        生成物 —— 缩略图 + 人脸裁剪图（可随时重建）
│   ├── thumbs\<fileHash[:2]>\<fileHash>_<size>.webp     200/400/800 宽的 WebP
│   └── faces\<faceCode[:2]>\<faceCode>.jpg              160px 人脸裁剪图
└── db\           应用状态
    ├── photolib.db (+ -wal / -shm)     SQLite 主库
    └── imports\ / exports\             导入原件归档 / 导出产物
```

**三条硬约束**：

1. `photo\` **绝对只读** —— 不写、不删、不改名。
2. 缩略图**不进 `photo\`**（保持原图区干净）。
3. 缩略图**不入库** —— 路径由 `fileHash` + size 推导。

**备份** = 停服务 → 拷贝 `db\` + `thumb\`。**迁移** = 拷贝三个目录 → 改 `PHOTO_ROOT` → 启动。

```powershell
# ⚠️ 先停掉 photo-browser 服务（Ctrl+C）。服务开着时拷走的是 SQLite 的 WAL 中间态，

code\.venv\Scripts\python.exe code\src\tools\backup.py list                              # 列已有备份
```

## 十二、常见问题（FAQ）

**Q：页面打开了但照片列表是空的？**
照片要先放进图片目录、再在「扫描任务」里启动扫描才会被收录。库为空时界面照样起得来，请用 `.\start.cmd --check-only` 体检。

**Q：「待确认」「我不同意」都是空的？**
这是**正确行为**。自动归属只用人工确认过的样本算质心，刚上手时还没有确认样本，需要先人工确认几张脸。

**Q：老照片的年份 / 地点是错的，能改吗？**
能。照片详情里分别有「修正拍摄年代」和「修正地点」——改的是照片级标注，**原图不动**，随时可「恢复自动」。详见[三大核心能力](#三三大核心能力)。

**Q：双击 `start.cmd` 一闪而过 / 报脚本禁止运行？**
脚本本身是 `.cmd`，不受 PowerShell 执行策略约束。若仍异常，请在仓库根目录的命令行里手动执行 `.\start.cmd` 查看报错。

**Q：端口 8765 被占了？**
换端口：`.\start.cmd --port 8799`。注意：端口被占时，8765 上可能跑着**另一个库**的服务，请在浏览器确认数据是否一致。

**Q：改了前端代码没生效？**
改完前端要重新 `npm run build`；本地热改用 `.\start.cmd --dev`（开 5173）。并确保 `dist/` 已构建（否则根路由只返回 JSON，页面全 404）。

**Q：怎么恢复误删的照片？**
软件**不删除原图**，也不备份 `photo\`。原图删除只能靠你自己的文件备份找回；`backup.py` 只恢复索引（数据库 + 缩略图）。

### 数据库要点

- **10 张表**：`pb_family` / `pb_person` / `pb_person_category` / `pb_place` / `pb_photo` / `pb_face` / `pb_person_centroid` / `pb_photo_person` / `pb_scan_job` / `pb_review_log`。
- **唯一数据源**：`code/src/database/pb_*.txt` → `sqliteCodeGenerator.py` → `common/sqliteCommon.py`。**业务层禁止裸 SQL**。
- **不用 ORM**：原生 `sqlite3` 读写双连接 + PRAGMA（`journal_mode=WAL` / `foreign_keys=ON` / `busy_timeout=5000` …）。
- **单写入者**：SQLite 硬约束，子进程只做 CPU 计算，主进程单线程批量写库；每线程一个只读连接（正确性要求，非优化）。
- 老库升级：跑一次 `tools\build_db.py`（幂等，只建缺的表）。

### 启用脚本为什么必要

照手敲命令有六个坑（其中三个静默）：工作目录必须是 `code\src`、必须用 `code\.venv` 解释器、`local_settings.py` 缺失回落默认、缺 `dist/index.html` 退化为只返 JSON、端口被占可能跑着另一个库、`.ps1` 可能被策略拦。`serve.py` 逐条查完再启，查不过就不给启动。
